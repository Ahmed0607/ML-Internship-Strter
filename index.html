Structured Content Archetype Clustering: Moving Beyond Heuristics

Built on the FlyRank ML Internship dataset (https://flyrank.ai).

1. Abstract

This project identifies performance archetypes across a large-scale content inventory to improve editorial prioritization. A rigid heuristic rule was initially built to flag "Stale Visible Pages," but it struggled to differentiate between stable evergreen content and genuinely decaying pages, performing worse than random guessing (Precision@50: 0.320 vs Base Rate: 0.511). To solve this, an unsupervised K-Means clustering model was developed on an 80/20 client-grouped split to group pages by multi-dimensional behavioral patterns. By calculating proximity to an identified "At-Risk/Declining" cluster centroid, the model successfully outperformed the baseline, achieving a Precision@50 of 0.520. This proves that mathematical clustering provides a safer, more accurate queue for content reviews than simple SQL-style thresholds.

2. Introduction / Problem Statement

When prioritizing content for updates, simple rules (e.g., "rewrite if older than 180 days and impressions > 500") are often too rigid. They cannot distinguish between a page that is organically decaying and a static utility page (like a Privacy Policy) that naturally receives high traffic but never needs a rewrite. This project replaces arbitrary human thresholds with unsupervised machine learning to discover organic, mathematically backed performance patterns.

3. Data

This analysis uses the FlyRank/internship-warehouse release (v20260703). The grain is a single pseudonymized content item's aggregated metrics for the mid-panel month of March 2026 (month=2026-03). I utilized fact_content_daily_performance joined with dim_content. I deliberately excluded raw text and product-derived context flags (like health_score) to avoid circular results and ensure the model discovered signals strictly from observed search behavior.

4. Methodology

  • Baseline: A multiplicative score penalizing pages that were stale (180+ days), highly visible (500+ impressions), and slipping in position.
  • Model: K-Means clustering (k=4).
  • Validation: An 80/20 Grouped Train/Test Split on client_id was used to ensure the model learned universal patterns rather than memorizing a specific client's website structure. Missing ranks were handled by median imputation.

5. Results

Evaluated on the 20% test split at K=50:

  • Base Rate (Random Picking): 0.511
  • Baseline Rule Precision@50: 0.320
  • K-Means Model Precision@50: 0.520

6. Limitations & Honest Framing

This is a decision-support tool based on observed correlations, not causal proof. A known limitation is our "semantic blind spot." Because the data contract excludes raw text, we cluster pages that behave the exact same way, but we cannot mathematically confirm if they cover the same exact topic. The model also occasionally misclassifies high-traffic "Evergreen" pages as "At-Risk" due to the heavy weight of raw impression volume.

7. Ranked Recommendations

The final output is a ranked CSV queue. Pages closest to the "At-Risk" centroid are surfaced for editorial review, specifically targeting metadata rewrites or content expansion.

8. Reproducibility

All code, queries, and execution environments are fully reproducible. The notebooks and data contracts are hosted in the project repository under work/notebooks/.
